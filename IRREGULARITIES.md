# IRREGULARITIES (Decision-Changing Only)

Only items that alter candidate validity, metric interpretation, governance, or slot allocation are listed here.

1. **Parent R0 (`0.2778`) Is a `CLAIM`, Not a `RECEIPT` in This Repo.**
   - *Fact:* `h33-h33-2-b2` (`c55bafc4...` / `baeae321...`) is rebuilt bit-for-bit (`0` pixel diffs across all `12,279,160` grid cells) from pinned `scored_h19_5.tif` + `existing_faults.tif` + `sample_submission.tif`, so parent *geometry* is 100% verified (the `SNAP` session additionally reproduced the same two byte streams from the final mask alone — mask + parent writer profile — so identity holds even if the recipe path regresses). However, its `0.2778` live number carries `evidence_class = CLAIM` (no organizer receipt is stored in this repo).
   - *Decision impact:* Every predicted live change (`MODEL`) is anchored to `0.2778` only up to `CLAIM` accuracy; if Slot 1 lands far from `0.2778`, parent baseline uncertainty (`CLAIM` vs `RECEIPT`) must be checked before attributing the gap to `SPACING`, `RELIEF`, or `MASS`.

2. **Public Bridge Mirrors Host Competition Rasters (`GEMSDOE`, `GEMSDOE24`, `GEMSDOE86`, `GEMSDOE92`).**
   - *Fact:* Input rasters pinned in `registry/data_manifest.json` were fetched from public GitHub repos under `buffedlizard55-lab/*`. DrivenData rules normally restrict redistributing challenge data publicly.
   - *Decision impact:* `GEMSDOE89` keeps `data/` and `.cache/` strictly git-ignored (zero competition rasters committed to git or `releases/`), and the human team owner should review visibility/licensing of upstream mirror repos before prize audit.

3. **`training_features.tif` Contains `-3.4e38` Float32 Sentinels Inside the Footprint (`IR-DEC-17`).**
   - *Fact:* Bands 1–8 and 18 contain `-3.4028235e38` nodata sentinels inside `sample_submission.tif`'s valid footprint (e.g., `635,517` pixels in band 18 `iso_grav_anom_hg`), where `np.isfinite()` is `True`.
   - *Decision impact:* Any feature computation or leakage canary must mask `band <= -1e30` to `NaN` (`tools/build_spacing.py` enforces this; `SPACING` geometry itself uses only binary `scored_h19_5` and `existing_faults`).

4. **Catalogue Hide-and-Recover `PROXY` Is Structurally Blind to `>=3 px`-Collar Edits on Long Strands.**
   - *Fact:* Because R0 was pruned at `d_cat > 2.0 px` and new variant dots obey `d_cat >= 3.0 px` (the exact 3-pixel DTI kernel radius), moving dots on `>=6`-dot strands leaves DTI on held-out `existing_faults.tif` (`PROXY`) invariant to 6 decimals (`0.038424`, 95% CI `[0.03285, 0.043997]`).
   - *Decision impact:* Never rank or gate `SPACING` (or other `d_cat >= 3 px` collar-respecting edits) by catalogue hide-and-recover `PROXY`; use physical ridge-jitter sensitivity (`MODEL`) and off-catalogue USGS SGMC fault coverage (`PROXY`, `https://doi.org/10.3133/ds1052`) for diagnostic direction, and treat only live `RECEIPT` deltas `>= 0.01` as evidence.

5. **`SPACING` 2D Lateral Arms (`poisson`, `lattice`) Trade Ridge Alignment for Packing Clearance.**
   - *Fact:* On R0's 834 active strands, reducing `<3 px` neighbor pairs by `29%–33%` (`poisson` / `lattice`) forces ~`79%–85%` of moved dots `1–2 px` laterally off the 1-px `h19_5` skeleton, dropping active-strand 3-px ridge coverage from `0.710` to `0.513–0.558` (`MODEL` `-0.010` and `-0.007`).
   - *Decision impact:* Only `alongstrike` (`100%` ridge retention, `MODEL` `+0.002`) is eligible for Slot 1; `poisson` and `lattice` are held strictly conditional on `alongstrike` surprising positively (`>= +0.010`).

6. **Upstream `MASS` Repeat Submissions Show Non-Zero Score Spread or Unverified Claims.**
   - *Fact:* Upstream ledger entries for `h33-h33-2-b2` and `MASS` cousins (`GEMSDOE32` / `GEMSDOE49` / `GEMSDOE55`) are `CLAIM` rows without verified receipts in this repo, and `scored_h19_5.tif` is binary (`{0, 1}`, `121,131` pixels) with no continuous ranking stored in the parent raster.
   - *Decision impact:* Reinforces the brief's `< 0.01 = no evidence` threshold and prevents over-interpreting sub-`0.01` differences across `SPACING`, `MASS`, and `RELIEF`.

7. **Missing Human Operational Inputs (`TOP_PUBLIC`, Weekly Slots, Deadline Verification).**
   - *Fact:* `TOP_PUBLIC`, slots used this rolling week, and organizer confirmation of the `2026-12-03` deadline cannot be fetched without accessing `drivendata.org` (barred by ToS).
   - *Decision impact:* Slot pacing in `SLOT_PLAN.md` and `README.md` leaves explicit placeholders for the human to fill before uploading Slot 1.

9. **The Brief's "Best Files Sit at Block-Density CV 0.51-0.59" Has No Block Size, and R0 Is Already Inside It at 12-15 km (CONCENTRATION session, 2026-10-23).**
   - *Fact:* MEASURED on R0 with the repo's density-CV definition (std/mean of dots per footprint pixel over blocks with `>= 50 %` footprint): **1.870** at 1 km, **1.146** at 3 km, **0.899** at 5 km, **0.638** at 10 km, **0.580** at 12 km, **0.516** at 15 km, **0.439** at 20 km (any-footprint variant: 1.397 / 1.179 / 0.961 / 0.801 / 0.552 at 2 / 3 / 5 / 10 / 15 km). The brief's band is therefore satisfied by R0 itself at 12-15 km, and is ~0.3 CV units away from every file in the fleet at the 5 km block size used by the earlier CONCENTRATION experiments. `GEMSDOE84` reached the same conclusion independently in `evidence/r0_concentration_variants_20261023.json`.
   - *Decision impact:* **do not target the band**. `CONCENTRATION` is run on the mechanism (known-fault prior), not on a CV goal, and CV is reported as an instrument only. A future session that picks a block size to "hit 0.55" would be fitting an unstated definition; that is why the prior, not the CV, sets the arm's direction.

   - *Fact:* `tools/build_ledger.py` regenerates `ledger/submissions.csv` from per-axis readers, but had none for `SNAP` (docstring and readers covered `SPACING`, `RELIEF`, `MASS` only), so the first rebuild in this session removed all three `SNAP` rows while `tools/check_ledger.py` flagged their release files as orphans.    - *Decision impact:* both tools are fixed and the rebuild is now verified to reproduce all 127 pre-existing rows field-for-field before adding this session's 3 (the integrated writer also normalizes CSV line endings to LF) (`_snap_rows()` reproduces the SNAP notes including their original `1.0`/`1.42`/`2.0` formatting). Any future session that adds an axis **must** add its own `_<axis>_rows()` reader or its ledger rows vanish on the next rebuild. The start gate's "2 FAIL" output in this session was a tool artefact, not missing data.

12. **The 2 km H19 CONCENTRATION Family Saturates and Is Not a Clean 5 km Scale Control.**

The 15% and 20% 2 km doses additionally require a ≥+0.010 receipt on their lower-dose parent. `tools/build_ledger.py` now has readers for both families, and the integrated rebuild preserves all 18 GEMSDOE89 rows.

13. **Unconstrained `12.8 km` Block Concentration Suffers Top-Block Hoarding and Circular-Cone Mimics (`CV_12.8km > 0.73`), Solved by Proportional Quotas + Strike Coherence (`arena/6e810001`).**

14. **TRACKB Corroboration-Composite "Leakage" Is a Footprint/Data-Availability Artifact, Not Signal (2026-10-24, TRACKB session).**
    - *Fact:* the TRACKB placement-corroboration composite (robust-unit mean of |TMI-HG|, isostatic-gravity slope, DEM scarp) scores an **unmasked** single-feature catalogue AUC of **0.8125**, which would look alarming against the 0.90 "stop" line. But `robust_unit` maps nodata/sentinel pixels to 0 while the catalogue lies inside the finite footprint, so this is driven by data availability: the plain "band-3-is-finite" flag alone scores AUC **0.7892**. **Footprint-masked, the composite drops to 0.5431**, matching the committed 19-band canary (max 0.5688). Verified in `tools/build_trackb.py` and `registry/leakage_canary.json`.
    - *Decision impact:* no leakage; the canary gate is evaluated footprint-masked (the scored region) so a data-availability artifact cannot falsely trigger "stop and investigate." The composite only re-ranks **legal** corridor pixels already at `d_cat >= 3 px`, never selects regions or overrides gates. If a future feature shows a high raw AUC, mask to the footprint before concluding leakage.

15. **TRACKB Rasters Are Held Out of the Weekly Slot Queue; the Phase-1 Jitter MODEL Is a Structurally-Biased Floor (2026-10-24).**
    - *Fact:* the cross-strike jitter MODEL (`registry/build_reports_trackb.json`) prices the TRACKB concentration negatively (central −0.002 / −0.012 / −0.021 at 2.5 px; loss shrinks toward break-even at the 3 px kernel-radius GeoDAWN uncertainty). Catalogue hide-and-recover PROXY and surrogate DTI are invariant (every edit at `d_cat >= 3 px`, cf. item 4).

Its primary product is the 1,520-trace GeoJSON/atlas inventory; do **not** spend a Phase-1 slot on `TR10`/`TR20`/`TR30` by default. The negative MODEL is a floor, not a forecast; only a live receipt could falsify, and the H19-surrogate's bias is stated on the mechanism card so a negative receipt is interpretable.
