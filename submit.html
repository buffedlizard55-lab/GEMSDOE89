Before opening the contest form

  • The separate selector has marked the exact file OK TO SUBMIT. A format PASS by itself is not enough; the current file above is not cleared.
  • Confirm the competition rules, current deadline, account/entity quota, and available rolling-week slots on the official competition page.
  • Verify the exact GeoTIFF SHA-256 in the run card and ensure that no other file or twin is selected.
  • Use a single-band GeoTIFF (`.tif`) or a `.zip` containing exactly one GeoTIFF, matching the sample file's CRS, shape and geotransform.

Form workflow for a future promoted file

  1. Sign in to the user's own DrivenData account and open the GEMS Prize submission form.
  2. Choose the explicitly promoted `.tif` (or a zip containing only that one GeoTIFF). Use an all-finite zeros-outside file only. Do not upload NaN research twins. Changing encoding is not a new scientific candidate.
  3. Use the promoted file stem as the submission name. For example, a future promoted stem will look like h89-...-<sha8>; use the actual promoted run-card stem, not this placeholder.
  4. Paste the run-card note into the optional Note field. The project checks that it is no longer than 140 characters.
  5. Review the selected filename and note, then submit. This repo never automates this action.
  6. Save the submission-page receipt and copy its exact score and date into the ledger as ORGANIZER-CONFIRMED. Do not substitute a projection, local holdout, or undated leaderboard screenshot.

What the project validates automatically

  • Input SHA-256 pins and reproducible parent identity.
  • Whole-segment spatial holdout with visible-catalogue-only derivations, buffer, exact visible-pixel masking, pooled DTI, and a spatial confidence interval.
  • Single-feature leakage canaries and pre-placement/final-raster registry checks; any correlation or overlap duplicate threshold stops promotion.
  • One band, float32, EPSG:32611, sample-grid shape/transform, no NaN or infinity anywhere in the upload raster, values in [0,1], and exact masking of known catalogue pixels.
  • A unique filename, ledger hash check, short form note, and a machine-readable JSON run card.
